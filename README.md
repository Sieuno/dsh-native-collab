# DSH Native Collab · 原生协作增强

**DeepSeek Harness Agent 协作增强（基于原版插件）**：在 DeepSeek Harness (DSH) 官方协作系统之上提供增量扩展，包括动态模型来源选择、树级共享自动消息额度，并优化委派提示词，遵循 MIT 许可。

本项目为**非官方社区插件**（非官方发行版，亦无官方背书）。

[English](README.en.md) · [安装指南](docs/INSTALL.md) · [常见问题 (FAQ)](docs/FAQ.md) · [测试说明](TESTING.md) · [反馈](https://github.com/Sieuno/dsh-native-collab/issues)

## 支持的 DSH 版本

本插件支持 **DeepSeek Harness 0.2.2-rc.2、rc.3、rc.4 和 rc.5**，运行环境要求 **Node.js ≥24.9.0**。

- **旧版宿主说明**：新架构不再支持 DSH 0.2.1 或旧版 0.2.2-alpha / rc.1 架构。若仍在使用旧版 DSH，请继续使用已发布的插件版本 **0.3.5**。
- **未来版本说明**：本插件不声明对后续未知预发布版或所有 0.2.2 变种的兼容，后续宿主更新需经审查后另行适配。

## 架构与核心变化

在 DSH 官方已统一 Team 与 Subagent 协作树的基础上，本项目从以往的「整套替换官方协作运行时」重构为**「在官方协作插件上做增量扩展」**：

- **完全复用官方核心**：直接复用宿主安装的官方工具主体，保留官方的参数校验、模型适配器校验、权限认证、成员发现、会话创建、完成通知、冷恢复与任务板功能。
- **轻量局部拦截**：仅在官方工具调用的局部上下文中注入模型策略与通信门禁，不替换全局后台服务，不写回或强行固定整份 Agent 预设。
- **移除历史冗余**：官方团队已具备同一协作树下的同构通信与成员管理，新版移除了旧版插件独立的 Team 名册、自定义协作面板及「Team / Subagent 身份互转」机制。

## 主要功能

| 功能项 | 说明 |
|---|---|
| **动态模型来源** | 针对新创建的子 Agent 提供三种模型来源：`conversation`（默认，沿用会话授权）、`settings`（每次读取当前原生子模型设置）、`all`（每次读取已注册提供方，具体模型仍经官方适配器校验）。仅作用于 fresh 子 Agent 委派，fork 保持官方参数与继承规则。 |
| **共享自动消息额度** | 默认 **32 次**，整棵协作树所有 Agent 共享，防止多 Agent 协作死循环。仅对成功接收的普通模型消息计数（发送失败退还，官方完成通知不消耗），树内收到用户输入/提问回复或进程重启时清零。通过 `task_result: true` 向直属父级提交任务报告可获豁免。 |
| **精简委派指导** | 插件会优化委派提示词：小任务直接处理、减少重复上下文、必要阻塞时沟通；充分利用官方的自动结果交付机制。 |
| **官方原生配置与面板** | 递归深度与并发上限由官方子智能体设置原生管理，插件不再维护重复副本；插件详情页提供简洁设置表单；任务进度统一在会话内的官方 Team 面板或任务卡片中查看。 |

### 1. 动态模型来源

插件为新创建子 Agent（`subagent` 工具）与模型发现（`list_subagent_models`）提供三种动态来源模式：

- `conversation`（默认）：沿用会话已保存的原生子模型授权；无记录时遵循官方父模型限制。
- `settings`：每次查询或显式选模时读取当前官方子模型设置，不使用旧会话列表代替当前设置。若当前设置关闭了子模型选择，则拒绝显式选模；未显式选模仍按官方继承规则运行。
- `all`：每次使用当前已注册的模型提供方。适配器公布的模型可被列出，未列出的精确模型 ID 仍须通过官方适配器校验才能创建。

动态来源不会改写会话历史中的授权记录，不会跳过官方对模型存在性、推理等级及提供方能力的校验。`subagent_fork` 保持官方的模型继承与配置约定，不额外注入选模参数。设置页仅保留模型来源和自动唤醒消息上限两项；模型来源默认选择「官方默认策略」，不影响官方已有的选模能力。

### 2. 消息投递

**说明**：本插件不再提供把消息排队到后续轮次的模型侧 `queue` 选项，统一复用官方 `send_message` 的 `steer` 投递机制：目标 Agent 在步骤边界接收指导，空闲目标可开始新轮次，不强制打断当前正在进行的模型请求或底层工具调用（此调整不影响官方用户侧的排队投递）。传入旧版 `delivery` 参数会收到错误提示。发送成功仅表示目标收件箱已接收，不代表已经处理完毕或生成回复。

### 3. 共享自动消息额度

为防止多 Agent 自主协作时陷入失控循环，插件引入了树级共享自动消息额度：

- **计数规则**：默认上限 **32 次**，同一棵协作树内的所有 Agent 共享。每条经本插件适配的官方 `send_message` 且被成功接收的普通模型消息计 1 次；发送失败会退还预留额度。
- **重置机制**：协作树内只要接收到用户输入或用户对提问的回复，额度立即清零重置；进程重启后也会重新计数。
- **额度耗尽表现**：达到上限后，仅拒绝该次消息发送（返回明确错误提示），不停止、取消或中断任何 Agent，亦不限制用户后续输入或同一 Agent 的内部思考。额度耗尽后应等待人类介入，不应循环重试。
- **结果报告豁免**：官方任务完成通知不经过该计数门禁，不消耗额度。此外，子 Agent 可使用 `task_result: true` 为已完成任务向**直属父级**提交最终结果报告，该特定路径可获豁免（普通对话、同级或向下消息不可冒用该标记绕过限制）。
- **作用边界**：门禁仅约束经本插件适配的模型工具；其他外部插件若直接调用原生底层服务 API 则不经过此限制。

## 使用建议

- **轻量协作定位**：本插件适合日常项目维护、原型开发和轻量多角色探索等场景。若需要复杂的团队编排与大规模流水线，建议评估更完整的专业团队协作方案。
- **任务委派节奏**：小任务或紧耦合工作优先由当前 Agent 直接处理，具有明确分工收益时再委派，减少不必要的上下文复制。
- **利用原生完成通知**：父 Agent 仍由宿主加载时，官方会在子 Agent 完成后回传结果，并唤醒空闲的父级，通常无需再用 `send_message` 重发总结。结束当前轮次不影响唤醒；但完成通知不会自动恢复已释放的父实例，具体区别见 [FAQ](docs/FAQ.md)。
- **具名协作与 Team**：普通子 Agent 即可具名协作并进行同树通信；仅在需要共享任务看板或持续协调分工时开启会话级 Team 模式。

## 安装与配置

### 安装命令

使用包名安装到你当前使用的 Profile：

```sh
dsh plugin --profile <profile> add @sieuno/dsh-native-collab
```

> **说明**：在 0.4.0 正式发布至 npm 仓库前，直接运行包名安装命令获取到的仍是旧版 0.3.5。发版前离线体验请使用构建出的 `.tgz` 安装包（`dsh plugin --profile <profile> add /path/to/sieuno-dsh-native-collab-0.4.0.tgz`）。正式发布后即可直接通过上述包名命令安装。

### 生效与配置流程

1. **重启 Profile**：安装、启用或禁用整个插件后，需正常关闭并重启同一 Profile（单纯刷新网页不等于重启服务）。
2. **插件设置表单**：在「插件 → 已安装」中打开本插件详情页即可看到设置表单，提供「Subagent 模型来源」和「自动唤醒消息上限」两项设置；修改后点击「保存」即可立即对后续工具调用生效。
3. **原生运行限制**：递归深度、并发数量上限、Team 模式开关及任务板均直接使用官方原生设置入口。
4. **停用插件**：请使用插件包的总开关，再重启同一 Profile；不要只关闭内部组件。

## 旧版本升级与注意事项

- **旧版身份互转记录**：旧版插件的身份互转功能曾在会话日志中写入过 `team/member` v3 扩展记录。新版插件不提供这些记录的自动迁移，亦不保证原生能够无损接管这些历史会话。升级前请**务必先备份 Profile 配置与会话数据**，并在独立 Profile 的新会话中验证使用。
- **启动残留清理**：若升级或卸载旧插件后 DSH 无法启动，通常是因为 Profile 目录下的 `cordis.patch.yml` 或启动器生成的 `*.patch.json` 仍残留对旧插件已废弃子路径（如 `/subagent`、`/agent-team`、`/tool-*`）的引用。请参考 [常见问题 (FAQ)](docs/FAQ.md) 仅清理本插件的失效条目，切勿清空整份 patch 或删除用户数据。
