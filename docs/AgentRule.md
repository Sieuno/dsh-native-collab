# Agent 仓库维护要求

1. **发布说明**：Release 只记录面向使用者的更新，不放入仓库和源码维护相关内容。
2. **临时资料**：过程资料、评估报告、参考文件及临时打包、测试产物放在仓库外。
3. **README 文档**：[中文 README](../README.md)和[英文 README](../README.en.md)只允许修改宿主支持版本；其他修改均需明确列出修改内容，并取得许可后才可进行。
4. **模块化提交**：以单一修改目的组织 commit，清楚说明修改内容与原因，便于审查、追溯和单独回退。同一目的涉及的源码、对应测试及必要文档可一并提交；不同目的的修改即使位于同一文件，也应拆分提交，不得混入同一个 commit。
5. **Markdown 文档维护**：除非确有必要，不应仅因开发过程需要或版本号更新而修改 Markdown 文档内容。CHANGELOG 除外，但应以发布为节点，根据最终更新结果维护，避免随开发过程反复改写或回退。
6. **分支生命周期与清理**：
   - `main` 与 `Develop` 为长期分支，保留，不作为临时分支清理。
   - **Feature 分支必须合入 `main` 后才可移除**；仅合入 `Develop`、发布测试版或关闭关联 Issue，都不构成删除 Feature 分支的条件。功能仍处于 Develop 测试阶段时继续保留原 Feature 分支。
   - **release、fix 等其他临时分支，在合入 `Develop` 或 `main` 后即可移除**，无需等待同时进入两个主干；清理已结束用途的远端分支及对应本地分支。
   - 删除前重新获取远端最新状态，核对当前分支头的实际提交包含关系及 PR 合并记录；不得仅凭 PR 已关闭判断已合并。有尚未合入的新提交、仍需使用该分支的未合并 PR 或未结束工作时，应保留。远端分支头在核验后发生变化时停止删除，重新检查。
   - 分支清理只移除符合条件的分支引用，不顺带删除版本标签、GitHub Release、npm 版本、测试数据或未跟踪文件；不得为了清理分支而将仅计划在 Develop 测试的 Feature 提前合入 `main`。
