# 常见问题

## 装好了，为什么还没接管协作功能？

安装只添加管理入口。先按[安装说明](INSTALL.md)关闭热重载，用插件自己的总开关查看并确认，再完整重启。不要逐项打开组件开关。

## 显示 hmr-active，不能确认

热重载还在运行。新建安装说明里的小覆盖文件，停止当前服务，再带 `--patch` 启动。同一进程内改文件或刷新页面不够。本插件故意拒绝在热重载中切换，避免正在工作的服务被意外替换。

## 显示 higher-priority-override / external-derived-reference

别的 home/命令行覆盖也在控制这些组件。先备份，检查你自己额外传入的 `--patch` 文件和 home 级配置，处理冲突后重新查看计划。不能只删界面报出的几个字，也不要清空整份 patch。

## 显示 configuration-changed-review-again / plan-expired-or-used

查看计划后配置变了，或者计划已用过/过期。关闭确认框，重新查看最新变更，再决定是否确认。不要重复发送旧确认请求。

## 显示目标缺失、歧义或不支持当前 preset

确认 DSH 版本及原生 Team Profile 都符合[安装前提](INSTALL.md)。如果你改过组件 id、普通 subagent/fork 或预设结构，插件可能无法确定该替换什么。这时拒绝修改是正常保护；请带错误码和脱敏后的相关配置反馈，不要强开所有派生行。

## 显示 configuration-unavailable

可能是 Profile 不可写、读取失败，或配置形状无法处理。先查看 DSH 的具体错误，核对当前用户是否有写权限及启动的是不是正确 Profile。不要直接用管理员/root 运行作为通用解决办法。

## 已保存，为什么运行值没变？

保存的是“下次启动的偏好”，不是即时改变运行中的 Agent。等任务结束，停止并完整重启该 Profile，再重新打开插件页。只关网页再打开不算服务重启。

配额还有一个区别：旧 Team 仍保留建立时的上限和已用次数；需要新建 Team 才能观察新的默认上限。

## 五项运行、两项关闭，是不是漏装了？

不是。两项普通工具是根层占位，真正的创建/分叉工具在 Agent 预设里运行；按设计应该关闭。诊断中的“来源未知”也不能直接当作失败。

## 通信子选项显示“未设置”，复选框却打勾？

“未设置”表示没有显式写入这一项；运行中引导和完成后续聊的默认值为 true，所以可能仍勾选。以偏好、默认值和启动观察值分别理解，不要把“未设置”当成“关闭”。

## 表格右侧文字看不全

长操作名保持一行，在窄屏或 200% 缩放下可能溢出。横向滚动表格可看全，确认/取消按钮仍可达。

## 关闭后，为什么比原来多了两个原生组件？

本版关闭会固定启用五项原生根组件，其中 control/list 原来可能关闭。这不是历史恢复。同时，启用时复制的完整 preset 仍会留下；以后升级 DSH 可能需要重新核对。

## 已经直接卸载，导致会话打不开怎么办？

先停止相关服务，保留当前配置和会话数据。不要清空 patch，不要删会话或用量记录。

在兼容的 DSH 环境，通常需要重新安装**原来使用的同一版本、同一包名的安装包**，按安装说明关闭 HMR，再尝试用插件总开关完成关闭，之后正常卸载。若仍不能关闭，不要继续强行卸载。若仍被阻断，应检查安装前备份与当前配置差异，只处理相关覆盖；完整恢复备份也会丢失备份之后的配置改动，必须先核对。

## 怎么反馈问题？

在本仓库 Issues 使用问题模板，附 DSH/Node/插件版本、Profile 类型、重现步骤、错误码和截图。先遮住浏览器访问 token、API key、会话内容和私人路径。无需上传整套 Profile 或原始会话日志。
