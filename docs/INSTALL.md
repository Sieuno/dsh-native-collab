# 安装与使用指南

从 **0.3.1** 起，**同一个包**支持 DSH 0.2.1（自 rc.1 起）和 0.2.2 系列，含预发布版；包内版本声明为 `>=0.2.1-rc.1 <0.2.2-0 || >=0.2.2-0 <0.2.3-0`。0.3.0 及更早版本仅支持 0.2.1 系列。插件要求 Node `>=22.19.0`，使用 DSH 0.2.2 时还需满足宿主的 Node `>=24.9.0` 要求，不能用插件下限降低宿主要求。CI 锁定版本用于可复现回归，不代表系列支持的上限；测试覆盖与真实 Host 验收的区别见 [测试说明](../TESTING.md)。

## 1. 安装与启用

**前提**：同一 Profile 需启用官方“智能体团队”实验 bundle（`@deepseek-ai/dsh-experimental-agent-team-profile`），提供插件接管所需的原生服务条目。默认 Web Profile 不一定包含它；本插件不会为缺失或重复的原生提供者强行接管，也不应通过版本豁免绕过未知版本。

1. 在**你当前使用的 Profile** 下安装，无需先停止正在运行的实例（安装只向该 Profile 写入依赖）。把 `<profile>` 换成实际使用的 Profile 名（GUI 默认通常是 `web`）：

```sh
dsh plugin --profile <profile> add @sieuno/dsh-native-collab
```

若使用本地或离线包，把包名换成对应的 TGZ 包路径。

2. 关闭并重新启动该 Profile，然后进入插件管理页面。升级替换正在使用的旧版本时，建议先关闭该实例，避免 Windows 上的文件占用。

## 2. 设置配置与自动保存

- **子智能体设置**：原生设置页不可用时，本插件提供代理设置。最大递归深度与并行上限自动读取，合法修改后自动写回当前 Profile 的原生 `subagent` 条目，不另存副本；原有深度规则不变，后续准入和切回原生服务仍使用同一配置。
- **自动保存**：子智能体设置和增强偏好修改后自动保存，失败会显示在对应区域；无需手动读取或保存。
- **无需手动改配置**：普通配置修改无需编辑配置文件，也不涉及服务切换。
- **生效机制**：
  - **模型来源**：保存后立即应用于后续的模型查询与子 Agent / Team 成员创建。
  - **启动配置**：增强开关及连续自动唤醒轮数上限等核心设置，在关闭服务后正常重启同一 Profile 即可生效（单纯刷新网页不算重启）。

## 3. 核心机制说明

- **单一管理入口**：插件 Patch 只插入一个管理入口，统一托管后台协作服务。管理入口开启时加载增强能力；若关闭入口并重启，系统将自动切回原生服务。
- **预设适配**：针对已知 AgentPreset 进行纯内存动态适配，不修改或固定原预设文件，亦不影响未知自定义 provider。官方实验包的四个根层工具仍保持禁用。
- **连续自动唤醒轮数上限**：
  - 默认上限为 32 轮，由会话所有 Agent 共享，防止死循环。
  - 仅对无人类输入介入的连续跨会话自动唤醒进行计数。
  - 任一关联会话接收到人类输入即刻清零；计数仅保存在进程内存中，进程重启也会自动清零。
  - 子任务完成或停止结果向直属父级或 Team Lead 汇报不受此限。
- **任务进度查看**：请前往发起任务的对话中的 Team 面板或任务卡片查看，设置页面不展示实时任务流水。

## 4. 插件卸载

卸载前先禁用插件，重启同一 Profile 并确认原生服务已恢复，再移除插件；正常卸载会清理插件 Patch。常规使用无需手动编辑底层配置文件。若卸载、禁用或换版本后 DSH 无法启动（常见原因是 Profile 目录下的 `*.patch.json` 外部启动覆盖文件仍引用本插件），请按 [常见问题 (FAQ)](FAQ.md) 的启动修复步骤处理，切勿清空 patch 或删除会话数据。
