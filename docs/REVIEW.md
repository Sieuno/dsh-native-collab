# 项目审查要求

通用审查判据：规定一次改动**能证明什么、不能证明什么、可以怎样声明**。不绑定具体版本、具体缺陷或具体代码路径。命令与分层见[测试说明](../TESTING.md)，用户操作见[安装说明](INSTALL.md)与[常见问题](FAQ.md)。

## 证据分级

每项结论落到唯一层级，并写明范围与未覆盖项。

| 层级 | 典型入口 | 能证明 | 不能证明 |
|---|---|---|---|
| 静态阅读 | 源码、词典、清单、协议文本 | 字面量、键名、调用点、分支与导出存在 | 运行期取值、动态异常、真实加载顺序 |
| 构建语法检查 | `npm run build`、`node --check` | 可转译、JS 语法合法、产物与源码对应 | 类型正确、行为正确、宿主可加载 |
| strict 类型检查 | `npm run check:types -- --sdk-types-map <已有SDK声明映射.json> --type-root <已有Node声明目录>` | 插件 TS 源码在给定声明下无类型诊断 | 依赖声明内部错误、宿主全部源码、运行期契约 |
| 隔离模块加载 | `npm run check:load -- --sdk-map <已有SDK模块映射.json> --read-root <允许只读的依赖目录>` | 发货 JS 可求值、配置 schema 可构造、依赖门槛与接管拒绝生效 | 真实 Agent 行为、真实 Profile、浏览器交互（仅核对注册） |
| 单元契约 | `npm test` | 本地依赖、构建产物与元素/协议夹具下的契约 | 真实 Host、真实模型、真实浏览器 |
| SDK 集成 | `npm run test:sdk` | 匹配 SDK 下的投影、注册、通信、设置与生命周期 | 官方客户端与真实会话 |
| 官方协议 | `npm run test:client` | 真实客户端协议的离线连接断言 | 在线交互、焦点与窄屏表现 |
| 官方发现 | `npm run test:discovery` | 官方发现原文与结构的哈希核对 | 当前宿主版本兼容 |
| 真实宿主验收 | 临时配置、模拟模型、独立数据目录 | 安装、启用、保存、重启、恢复、卸载闭环与浏览器交互 | 全部兼容版本与全部用户环境 |

- 单层通过不得上推为整体通过；多层分别通过时逐层写清，不合称"完整验收"。
- "已修复/已验证"必须给出层级、范围与未覆盖项，例如"已改源码，静态阅读层，未运行单元测试"。
- 计数需给口径（范围、排除项、单位）；无口径的数字不写入结论。

## 声明纪律

- 文案与解释修改只能主张文案与解释的变化，不得作为功能修复的证据；逻辑、接线与判定条件未变时明说未变。
- 不以测试通过代替宿主验收，不以构建通过代替类型检查，不以类型检查代替运行正确。
- 只申报实际执行过的命令和实际打开过的界面；未运行的测试、未打开的 Profile、未访问的模型、未注入的失败路径一律写明未执行。
- 建议与现状分开标注：未实现的能力写成建议或限制，不写成当前行为；不为配合措辞改动事实。
- 不引用旧日志、旧包、旧工作树或总 diff 规模充当当前结果；证据失效即结论失效。
- 每条结论附带不能证明的部分；删除旧结论前确认它确实被新证据取代。

## 失败封闭

- 缺前提显式失败：缺少环境变量、映射文件、声明目录或官方资产时以非零状态退出，并给出可直接执行的提示，不静默跳过。
- 确需跳过时单独计数，并在结果中标记为未验证，不并入通过数。
- 不得用空对象、空实现、伪造导出、改动别名或吞掉二次注册异常来满足依赖。
- 状态、版本、路径不确定时拒绝，不猜：未知状态拒绝接管，未知版本拒绝适配，多个候选路径拒绝写入并列出候选。
- 检查与比对入口只读：`--check` 只报告差异，不重写文件，不自动修复。
- 部分成功视为失败：多文件写入、多步装配或分级结果出现部分完成时返回失败，保留可核对状态，不显示成功。
- 门禁不可绕过：不得用 `|| true`、跳过标记、删除失败断言或隐藏异常来销项；失败断言只能修正用例，不能删掉契约。

## 工件与仓库卫生

- 临时产物只进忽略目录 `.test-artifacts`；生成目录、解压目录、构建快照、归档包与日志不入库。
- 不把问题清单、回归报告、维护笔记、审计报告、交接表单与回写说明写入仓库；变更叙事由提交说明与更新日志承担。
- 历史由 Git 管理；不为一次修复复制测试或文档，不建以轮次、批次或版本命名的测试文件。
- 测试按功能维护并登记到测试入口，一个文件只登记一次；公共夹具集中复用，样例独立于实现常量。
- 交付工件放仓库外或忽略目录，本地记录哈希；不覆盖同名不同内容的版本。

## 文档与词典同步

| 对象 | 要求 |
|---|---|
| 双语词典 | 键集、嵌套结构与占位符一致；改一处同时改另一语言，事实对齐，不存在只有单语修复 |
| 用户文案 | 回答发生了什么、是否有修改、下一步做什么；状态不确定时写"不确定"，不暗示已保存或已恢复 |
| 占位符与错误码 | 只使用源码中真实存在的名称与代码；机器码放折叠详情，正文用普通概念，不翻译、不改拼写 |
| 参数与文件名 | 只写实际存在的旗标、参数与文件；不设计未实现的按钮、跳转、自动修复或自动恢复 |
| 危险动作 | 后果、重启要求、数据保留与操作顺序不因精简而消失；确认按钮使用动作明确的措辞 |
| 状态语义 | 区分未发起写入、写入结果未知、部分写入、文件已写入与服务已生效；固定状态写明不是历史回滚、不随上游同步 |
| 用户文档 | 安装命令、默认值、重启要求与移除步骤随代码同批更新，不留过时路径与失效链接 |

## 安全与打包边界

- 路径与凭据扫描：交付内容不得含绝对路径、`file://`、家目录路径与凭据字面量；扫描只覆盖受控内容，不遍历依赖、生成测试产物与缓存。
- 白名单只收运行时必需：发货 JS、词典、图标、协议补丁、发布检查脚本与用户文档入包；源码、测试、依赖、开发编译产物与项目级 `.npmrc` 不入包。
- 禁止 vendored 依赖：不使用打包依赖字段，不把宿主 peer 复制进包，不改锁文件掩盖缺失。
- 宿主 peer 保持 optional：每个 peer 都声明为可选；声明的版本范围不代表已在该范围全部验证。
- 哈希、指纹与大小校验只说明同一文件未被替换，不是签名，也不证明与被测宿主匹配。
- 敏感输出：计划、日志与恢复记录可能含凭据和完整配置原文，只报告机器码、版本与脱敏目标列表；权限位不等于访问控制已配置。
- 修复手段限于插件自身：不改宿主源码或安装包、不扩权、不删除账本、不绕过适配器校验。

## 合并与删除判据

删除或合并前逐条核对；计入删除的一侧只要有一条不满足，即保留。

| 可合并或删除 | 说明 |
|---|---|
| 无引用 | 仓库内无链接、无脚本或测试读取，删除不破坏其他文档与命令 |
| 已被取代 | 同一结论有更新来源接管，旧文只剩历史价值 |
| 仅过程记录 | 轮次清单、逐项勾选、交接表单、回写说明、一次性审计行号 |
| 重复覆盖 | 同一契约多处断言，合并到功能文件并保留更强的断言 |
| 未覆盖真实契约 | 只断言字面量存在、只比较文案条数、只验证自造夹具状态 |
| 快照化 | 写死版本号、行号、计数或时间，没有基线即无法复核 |

| 必须保留 | 说明 |
|---|---|
| 唯一覆盖 | 唯一断言该契约的测试，或唯一说明该操作步骤的文档 |
| 真实契约 | 官方协议、官方发现、SDK 注册与生命周期、宿主装配顺序 |
| 安全校验 | 接管拒绝、迁移、锁、补偿，以及路径与凭据扫描 |
| 用户操作 | 安装、启用、保存、重启、恢复、卸载与误卸载修复 |
| 限制声明 | 非原子、不可回滚、数据保留、隐私与权限风险 |

执行顺序：确认无引用 → 确认存在接管来源 → 确认非唯一覆盖 → 确认不属于用户操作或安全校验 → 才可删除。删除不可恢复，需先向用户确认；提交说明写明取代关系。

## 适用范围与更新方式

- 本文是通用要求，适用于任何改动、任何审查者；不记录具体版本、具体缺陷、具体代码路径与具体条目编号。
- 分工：[测试说明](../TESTING.md)给出分层命令、文件数与外部前提（怎么跑）；[安装说明](INSTALL.md)与[常见问题](FAQ.md)给出用户操作（怎么用）；本文给出判定标准与声明纪律（怎么算通过、可以怎样声明）。
- 新增要求追加到对应小节，不新建过程文档、不新建审查报告；一次性记录按上一节判据合并或删除。
- 命令、分层或前提变化时同批更新本文与[测试说明](../TESTING.md)；两处冲突时，可执行命令与失败封闭优先，并修正另一处。
- 本文不记录具体时间、人员署名与仓库绝对路径；引用使用仓库相对链接。
